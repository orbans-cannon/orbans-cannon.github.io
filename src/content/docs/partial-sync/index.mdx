**開場問題**：為什麼 safety 與 liveness 必須分開處理？

## 規劃章節

<PartRoute timing="partial">

1. **DLS 與 GST 的實作面**：部分同步的定義與下界在[不可能性與下界](/impossibility/partial-sync/dls/)，本部分接著講怎麼設計協議：safety 永遠成立、liveness 依賴 GST。
2. **[PBFT](/partial-sync/pbft/)**：三階段、prepared 與 view change，以及為什麼拿掉 commit 階段會出事（附反例）。
3. **[HotStuff](/partial-sync/hotstuff/)**：線性 view change、鎖定規則、responsiveness，以及複雜度的精確敘述。
4. **[Pacemaker 與 view synchronization](/partial-sync/pacemaker/)**：Cogsworth 與 RareSync，補上 HotStuff 留下的黑盒。
5. **通訊與延遲**：下界在[不可能性與下界](/impossibility/cost/dolev-reischuk/)，本部分比較各協議離下界多遠。
6. **[2-chain 與簡化](/partial-sync/two-chain/)**：Tendermint、Jolteon／Ditto 與 Simplex。

</PartRoute>
