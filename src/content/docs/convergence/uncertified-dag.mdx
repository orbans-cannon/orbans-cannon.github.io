## 預計涵蓋

- **延遲從哪來**：certified DAG 的每個區塊要經過 Reliable Broadcast 或 consistent broadcast，多次往返。Cordial Miners 針對 DAG-Rider 與 Bullshark 指出 RB 的延遲；Mysticeti 針對 Narwhal 與 Bullshark 指出認證的多次往返，並另外列出兩個原因：每個 wave 才有一次 commit 機會，以及簽章的 CPU 成本。
- **Cordial Miners**：去掉 RB，用 blocklace 容納 equivocation，在本地排序時才排除；原文的延遲以「通訊輪」計（含 RB 內部的輪），與本站 DAG 頁的「DAG 輪」不同，預計逐條標明。
- **Mysticeti**：區塊只簽名不認證，每個區塊獨立 commit，原文聲稱達到 3 個 message round 的下界（引 Martin–Alvisi 的 fast BFT）；Sui 部署時從 Bullshark 換成 Mysticeti-C。
- **兩者並列**：Mysticeti 說兩者的 DAG 結構相似，但 Cordial Miners 每個 wave 只 commit 一個區塊；兩者不是前後代。
- **與下界的關係**：延遲下界的完整分類見 [延遲下界](/impossibility/cost/good-case/)。
- **邊界**：本站核對的兩份原文都是 arXiv 版，內文可能與出版版有差異，寫頁時核對。
